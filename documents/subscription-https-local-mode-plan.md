## 目标

1. 让公网订阅发布服务独立负责 TLS 域名、证书、续期和 Nginx HTTPS 配置。
2. 在“订阅与用户”中提供不启用 WireGuard 的“本机单独使用”入口。
3. 保持 Reality、主控/被控控制面和公网订阅三条能力边界互不隐式触发。

## 审计结论

### 应增加“本机单独使用”

当前本机订阅管理被菜单守卫绑定到 WireGuard `main` 角色，用户即使只管理一台服务器，也必须初始化主控和 WireGuard。实际订阅状态中的默认服务器源已经是本机 `main/local`，本地同步、用户订阅、流量和额度均不要求远端控制面。

因此应增加本机入口，但不新增持久化 `standalone` 角色。内部 `uninitialized` 继续表示“尚未启用主控/被控拓扑”，选择本机模式只进入本机菜单，不写控制面状态。

### 订阅证书必须独立触发

Reality entry 有域名也不代表存在本机证书。只有用户安装或更新公网订阅发布服务时，才需要解析订阅域名、复用或申请证书、配置续期，并生成 Nginx SSL 监听。

主控/被控控制接口继续通过 WireGuard 内网 HTTP 访问，不需要公网证书。

| 高 | 订阅端口输入路径不检查监听占用，换端口后旧防火墙规则也没有完整收尾 | 同配置的受管 Nginx 监听视为幂等自占用；其他监听一律失败且不杀进程；新旧端口与配置一起提交或回滚 |

## 固定行为合同

| 场景 | 行为 |
| --- | --- |
| 安装 Reality | 不因 entry 域名安装 acme.sh、证书或 Nginx |
| 选择“本机单独使用” | 不安装 WireGuard，不写主控/被控状态 |
| 初始化主控 | 只初始化 WireGuard 控制面，不提前申请订阅证书 |
| 初始化被控 | 只接入主控，不安装公网订阅服务 |
| 本机或主控安装订阅服务 | 独立确保订阅域名、证书、续期和 Nginx HTTPS |
| 订阅证书缺失或申请失败 | 安装失败，不写 Nginx SSL 配置，不降级 HTTP |
| 已有匹配证书 | 直接复用，不重复申请 |
| 本机转主控 | 保留已有 groups.json、订阅用户和本机服务 |
| 控制状态文件损坏或不可读 | 明确失败，不视为本机模式 |
| 本机模式执行同步 | 只同步本机，不访问 groups.json 中残留的远端源 |
| 本机模式发布订阅 | 只生成和发布本机 `main` 内容，不解析、请求或合并历史远端源 |
| 主控/被控控制服务 | 由 WireGuard 初始化与修复路径负责，与公网订阅服务无关 |
| 更新既有订阅服务 | 无论端口是否变化都复验域名、证书和配置 |
| 被控直调安装或同步命令 | 在共享入口失败，不安装证书、不修改 Nginx、不执行本机同步 |
| 主控控制面已关闭 | 仍可使用本机发布和本机同步，但不运行远端阶段，也不重装控制服务 |
| 本机转被控且存在活动发布或同步 cron | 阻止转换；不自动停服、删配置或改角色 |

## 菜单设计

### 未启用多服务器拓扑时

“订阅与用户”显示：

1. `本机单独使用`：管理本机订阅、用户、流量和维护，不启用 WireGuard。
2. `这台作为主控`：初始化 WireGuard 主控，并进入现有主控首页。
3. `这台作为被控`：初始化 WireGuard 被控并导入主控凭据。
4. `返回主菜单`。

状态文案改为“多服务器角色：未启用；可直接使用本机订阅”，不再把本机使用描述成“角色未完成”。

读取到损坏、非法或不可访问的 WireGuard 状态文件时，不显示本机首页，改为提示修复状态；不得用读取失败兜底为 `uninitialized`。

### 本机首页

本机首页只提供单机有意义的能力：

1. `发布订阅`：复用现有安装服务、自用链接、分享订阅、服务器和流量菜单。
2. `本机运行与维护`：本机同步、流量与限额、自动同步、状态备份。
3. `启用多服务器协同`：执行现有主控建链向导，保留本机状态。
4. `返回上级`。

不显示远端服务器、Peer、控制面地址、远端健康检查或远端错误清理。

本机模式执行同步时，统一在同步入口阻止远端阶段；即使历史 groups.json 中残留远端源或 `remote_enabled=true`，也只能应用本机计划。

### 主控和被控

现有主控、被控首页保持不变。主控继续拥有本机发布能力和多服务器能力；被控继续只处理接入、状态和控制面维护。

从本机模式初始化主控时保留 groups.json 和公网订阅服务。选择成为被控时，先检查公网订阅配置和受管同步 cron；任一仍活动就阻止转换并保持原状态，避免留下被控菜单无法治理的后台服务。仅有订阅数据、证书或未启用的历史源不阻止转换，也不删除数据。

## 订阅域名解析

订阅域名按以下顺序解析：

1. 命令显式传入的 `--domain`。
2. 已安装订阅配置中的 `subscribeDomain`。
3. 仅有一张通过域名、有效期和密钥校验的可用证书时，使用其受管文件名对应的主机名。
4. 交互模式询问用户输入；可展示现有 TLS 域名、`currentHost` 或 Reality entry 作为建议，但必须由用户确认。

自动模式不得根据 `currentHost` 或 `reality_entry_host` 自动申请证书。既没有 `--domain`、旧订阅域名，也没有唯一可复用证书时，应在安装依赖和修改 Nginx 前失败；检测到多张证书时要求显式 `--domain`，不得按文件遍历顺序选择。

`readNginxSubscribe()` 解析出的 `subscribeDomain` 是订阅服务自己的状态。删除其与 `currentHost` 的相等判断，并校验同一受管 server block 的 SSL listen、`server_name`、证书/私钥路径和端口一致性；域名不同于 Reality entry 或传统 TLS 域名属于正常情况。文件不存在、配置有效和配置损坏必须是三个不同结果，损坏配置不得降级成“未安装”。

## 证书处理流程

### 已有证书

1. 先用 `tlsCertificatePairExists()` 检查订阅域名对应的 `.crt/.key`，再用现有 OpenSSL 依赖验证证书可解析、当前有效、SAN 覆盖订阅域名且私钥匹配。
2. 只有完整且可用的证书对才能直接复用；过期、域名不匹配、密钥不匹配或不可解析均按证书待修复处理。
3. 可用证书不调用 CA，也不重复安装 acme.sh。
4. acme 管理的证书继续使用现有安装目标和续期链；自定义证书显示“需自行续期”，不安装无效的续期任务。
5. Nginx 配置校验继续作为最终加载检查，但不能替代证书域名和有效期校验。

### 缺少证书

交互模式：

1. 明确提示“公网订阅只提供 HTTPS，需要为该订阅域名申请证书”。
2. 用户确认后安装缺失的 acme.sh，并复用现有 `installTLS()` 签发流程。
3. 用户拒绝则取消订阅服务安装，不改变 Nginx。

自动模式：

1. 必须有显式 `--domain`。
2. 复用现有 `--tls-ca`、`--dns-api`、DNS 服务商和凭据参数。
3. 参数不足、签发失败或证书对未生成时返回非零。
4. 不进入交互，不退回 HTTP。

签发方式的网络前置条件必须分开：

- HTTP-01 在停止服务、开放 80 或调用 CA 前先复用 `checkDNSIP()` 校验订阅域名指向本机；校验失败时不改变服务和防火墙。
- DNS API 支持 NAT、代理和预先签证，不要求 DNS 公网地址等于本机 `publicIP`，因此不得调用该等值校验；签发完成后通过本机 SNI/TLS 探测验证 Nginx 实际加载的证书。

调用现有 TLS 流程时，只在受控作用域内把订阅域名传给 `domain`，完成后恢复 `domain/currentHost/tlsDomain` 等全局值，不能把订阅域名写成 Reality entry 或传统 TLS 域名。

### acme.sh 安装能力

从现有 `installTools()` 中提取已经存在的 acme.sh 安装段为可复用函数，供协议安装和订阅服务两个真实调用点使用。保持现有下载校验、固定提交解析、目录备份和软件包事务，不复制安装实现。

### 自动续期

acme 管理的证书成功生成后，复用 acme 安装时已有的全局 cron、现有 `installCronTLS()` 和逐证书 `--installcert` 目标。必须验证每个活动 acme 证书都保存了对应 `.crt/.key` 安装目标，续期后实际更新订阅使用的文件；不创建每域名一套新 cron，也不新增证书注册表。自定义证书不伪装成可自动续期。

`RenewTLS` 不得只按 `currentHost` 或目录首项覆盖单张证书。实现可直接利用 acme 已保存的安装目标并校验所有活动证书，无需另造续期框架；任一证书文件发生更新后只重载一次 Nginx，并执行本机 SNI/TLS 探测。回归必须覆盖传统 TLS 与独立订阅域名并存且签发日期不同的情况。

## HTTPS 配置事务

每次“安装/更新订阅服务”都执行完整预检，即使已经读到 `subscribePort` 也不能直接返回。目标状态由“期望域名 + 期望端口 + 证书对”共同决定；显式 `--domain` 或 `--subscribe-port` 与旧配置不同都触发重建。已有 `subscribe.conf` 无法完整解析时明确失败，不把损坏配置当成未安装覆盖。

订阅端口使用非破坏性检查：如果监听来自当前有效 `subscribe.conf` 且端口未变化，视为本服务自占用并允许幂等更新；其他 Nginx 配置、Reality、Xray、sing-box 或任意外部进程占用都直接失败，不询问杀进程，也不在本计划支持与其他 HTTPS 虚拟主机或 Reality stream 共用该端口。

安装顺序固定为：

1. 在共享入口验证角色状态；被控或损坏状态立即失败。
2. 以三态方式读取旧配置，解析并校验期望域名、期望端口和证书路径。
3. 非破坏性检查期望端口；仅放行当前受管订阅配置自己的监听。
4. 确认可用证书存在；需要时先完成 acme 安装和签发。
5. DNS API 签发不操作 Nginx、80 监听或防火墙。HTTP-01 先校验 DNS，再记录 Nginx、80 监听和防火墙原状态；仅临时停止已识别的 Nginx，其他监听直接失败，并在所有成功/失败路径恢复原状态与本次新增的 80 规则。
6. 确认证书安装目标和续期任务覆盖该订阅域名。
7. 确保 Nginx 可用，只创建订阅公开目录，不调用 `nginxBlog()`，不安装传统 TLS fallback 站点。
8. 备份现有 `subscribe.conf`、Nginx 服务状态和相关新旧端口防火墙所有权。
9. 开放期望订阅端口，生成只监听 SSL 的订阅配置并执行 `nginx -t`。
10. 应用 Nginx，使用订阅域名和本机地址执行 SNI/TLS 探测，确认加载的是目标证书。
11. 端口变化时只回收 padm 拥有的旧端口规则；配置、服务、探测或防火墙收尾失败时恢复旧配置、旧服务状态和旧端口状态。

证书阶段失败时不得创建或修改 `subscribe.conf`。Nginx 阶段失败时沿用现有配置和服务状态回滚；已经成功签发的证书与续期任务保留，避免重复请求 CA，并在错误信息中说明。

已有配置、域名、端口和可用证书均匹配时保持幂等，只执行配置校验、服务状态确认和本机 TLS 探测，不重复签发、开放端口或重写配置。

## 角色守卫调整

先收紧共享状态读取：状态文件不存在才生成合法默认状态；状态文件存在时必须明确给出合法 `.role` 和布尔 `.enabled`，并复用现有端口、地址、公钥、endpoint 和 Peer 校验器检查角色组合。`uninitialized + enabled=true`、缺少角色、错误类型、非法角色、主控/被控必需字段无效或畸形 Peer 都直接失败；合法 `main/controlled + enabled=false` 表示控制面已配置但当前关闭，不能误判为损坏。不得在归一化时过滤坏字段后继续。

新增一个最小的“本机发布者”守卫，允许有效的 `main` 和有效的 `uninitialized`，拒绝 `controlled`；角色读取失败或非法组合直接失败。守卫必须放在 `installSubscribe()` 等共享写入口，确保菜单、自动命令和内部调用行为一致，再替换下列菜单入口的主控守卫：

- 发布订阅
- 本机同步
- 本机流量与限额
- 本机自动同步设置
- groups.json 备份与恢复

多服务器、WireGuard、远端凭据、Peer 和控制面操作继续使用现有 `subscriptionRequireMainRole()`。读取失败不能再由 `subscriptionCurrentRoleNormalized()` 或其他调用点兜底成 `uninitialized`。

同步执行层在 `runSubscriptionGroupSync()` 的共享入口统一门控：有效 `uninitialized/main` 可运行本机阶段，`controlled` 和损坏状态在备份、配置或服务写入前失败；只有有效 `main` 且 `.enabled=true` 时才允许远端阶段。残留 cron 和直接执行 `SyncSubscriptionGroups` 也必须经过同一门控。

本机模式还要在远端订阅源解析和发布合并入口禁用远端作用域，不能只跳过 `runSubscriptionRemoteSync()`。即使 groups.json 中保留远端源、`allowed_sources=["*"]` 或缓存输出，本机发布、源选择和状态展示都只使用 `main`，且不得调用 `updateRemoteSubscribe()` 或任何远端健康/同步请求；原始远端数据保持不变，供恢复主控状态时继续使用。

公网订阅服务和 `subscriptionSyncReconcileLocalServices()` 都不再调用 `installSubscriptionControlService()` 或写 WireGuard Nginx location。主控初始化、被控初始化和显式控制面修复路径分别保证控制服务与内网 location；控制面 `.enabled=false` 后，发布或同步不得把它重新启动。被控控制 API 应用主控下发计划仍可重建本机核心配置，但不得刷新残留公网订阅配置。

从合法 `uninitialized` 初始化被控前检查活动 `subscribe.conf` 和受管 `SyncSubscriptionGroups` cron；存在任一项时失败且不写角色。此计划不实现跨公网服务、cron、WireGuard 和防火墙的自动拆除迁移事务。

## 实施步骤

### 1. 收紧角色状态读取

区分“状态文件不存在的合法未初始化”“组合有效的 main/controlled”和“损坏/不可读/矛盾状态”。复用现有 WireGuard 字段校验器，保留合法的已关闭主控/被控，错误状态停止并给出修复提示。

### 2. 增加本机入口

在角色选择页加入“本机单独使用”，新增本机首页，不写 WireGuard 状态；保留本机转主控的数据。转被控前如存在活动公网发布或受管同步 cron 则阻止转换，不自动拆除服务。

### 3. 分离本机与多服务器守卫

本机能力允许主控和合法未启用拓扑状态；被控仍拒绝。守卫下沉到安装和同步共享入口，覆盖自动命令与 cron；远端网络阶段只允许有效且已启用的主控。

### 4. 纠正控制服务所有权

从公网订阅安装和全部业务同步路径中移除控制服务副作用；主控、被控初始化与显式修复路径独立保证控制服务和 WireGuard 内网 Nginx location，关闭后不被同步重新启动。

### 5. 修正订阅配置状态读取

删除 `subscribeDomain == currentHost` 耦合，把配置读取改为三态，并校验订阅配置自身的 SSL listen、域名、端口和证书路径；损坏配置不按未安装覆盖。

### 6. 修正订阅域名解析

让域名候选和“证书可用”成为两个独立判断。删除 `currentHost/domain` 只要格式合法就视为可用 HTTPS 域名的旧行为，只把通过有效期、SAN 和密钥校验的唯一证书作为隐式候选。

### 7. 提取 acme.sh 安装函数

复用 `installTools()` 中现有实现，保持协议安装行为不变，并允许订阅服务按需单独安装 acme.sh。

### 8. 增加订阅证书准备阶段

在任何 Nginx 写操作前解析域名、验证证书、交互确认或执行自动签发；区分 acme 与自定义证书。HTTP-01 预检 DNS 并事务化恢复 Nginx/80 防火墙，DNS API 保留 NAT/代理能力。

### 9. 修正独立证书续期

复用 acme 已保存的逐证书安装目标和现有全局 cron，保证传统 TLS 与订阅证书都被更新；任何活动证书变化后只重载一次 Nginx，不新增逐域名 cron 或证书注册表。

### 10. 收紧订阅 Nginx 与端口事务

每次安装/更新都复验期望域名、端口和证书。允许当前受管监听幂等更新，拒绝其他占用且不杀进程；新旧端口、防火墙、配置、服务和本机 TLS 探测共同提交或回滚，并移除 `nginxBlog()`。

### 11. 调整本机作用域和维护菜单

复用现有本机同步、流量、限额、自动同步和备份函数；隐藏所有远端和 WireGuard 项，并让订阅渲染、源选择与状态展示只使用 `main`，不复制底层业务实现。

### 12. 更新自动命令和文档

更新 `InstallSubscription` 帮助、中英文 README 和菜单文案，说明 `--domain` 是订阅 TLS 域名，纯 Reality 后补装订阅会独立申请证书，并说明自定义证书不由 padm 续期。

### 13. 增加定向回归

补齐状态组合、命令绕过、本机远端隔离、控制服务所有权、域名、证书可用性、多证书续期、端口、防火墙、菜单、角色转换和失败回滚测试，再运行相关现有套件。

## 测试矩阵

### 证书与 HTTPS

- 已有匹配证书：复用证书，不调用 acme.sh 安装或 CA。
- 证书过期、SAN 不覆盖域名、证书/私钥不匹配或文件不可解析：不得视为可用证书，不写 Nginx。
- `currentHost` 有域名但无证书：不得直接写 Nginx。
- 订阅域名不同于 `currentHost`：仍能读取、更新并展示已安装服务。
- 多张证书且未指定域名：自动模式失败，交互模式要求选择或输入。
- 唯一证书文件存在但不可用：不得成为隐式域名候选。
- 交互同意申请：证书成功后生成 SSL 配置和续期任务。
- 交互拒绝申请：无 Nginx、证书和服务状态变化。
- 自动模式无域名且无证书：写操作前失败。
- 自动模式显式域名：使用现有 TLS 参数完成申请。
- 同端口显式更换域名：重新检查证书并重建配置。
- 已有配置但证书文件缺失：进入证书修复，不因 `subscribePort` 非空而跳过。
- `subscribe.conf` 存在但 SSL listen、域名、端口或证书路径损坏：明确失败，不按未安装覆盖。
- HTTP-01 DNS 未指向本机：在停止 Nginx、开放 80 和调用 CA 前失败。
- HTTP-01 遇到运行中的 Nginx：临时停止后在成功和失败路径恢复原状态。
- HTTP-01 遇到非 Nginx 的 80 端口占用：失败且不停止该进程。
- HTTP-01 临时新增的 80 防火墙规则：签发成功、签发失败和后续 Nginx 失败时都恢复；原有规则不受影响。
- DNS API 的 NAT 或代理场景：不执行 `publicIP` 等值检查，也不停止 Nginx或操作 80。
- acme.sh 安装失败、签发失败、证书落地失败：分别返回错误且不改 Nginx。
- 自定义证书：复用但提示自行续期，不创建误导性的自动续期状态。
- acme 订阅证书与 `currentHost` 不同：续期后订阅 `.crt/.key` 仍被更新。
- 传统 TLS 和订阅证书签发日期不同：全局续期仍分别覆盖，两张证书变化只触发一次 Nginx 重载。
- 同域名同端口更新且监听来自当前 `subscribe.conf`：按幂等成功，不误报端口占用。
- 期望端口由其他 Nginx 配置、Reality、核心或外部进程占用：写配置前失败且不杀进程。
- 更换订阅端口：新规则、配置和服务失败时回滚；成功后只回收 padm 拥有的旧端口规则。
- Nginx 配置或服务失败：恢复旧配置和原服务状态，保留已签证书。
- Nginx 启动但本机 SNI/TLS 探测失败：按 Nginx 阶段失败回滚。
- 订阅安装不调用 `nginxBlog()`，不创建传统 fallback 站点。
- 全部成功：订阅配置只包含 SSL 监听，不存在 HTTP 降级。

### 本机模式

- 未启用拓扑时显示本机、主控、被控三个入口。
- WireGuard 状态损坏或不可读时明确失败，不进入本机模式。
- 现存状态文件缺少 role、`uninitialized + enabled=true`、非法字段类型或角色必需字段无效时均视为损坏。
- 合法 `main/controlled + enabled=false` 仍识别原角色，不降级成未初始化。
- 进入本机模式不调用 WireGuard 安装、写状态或服务动作。
- 本机安装订阅服务和执行同步均不安装控制服务或控制面 Nginx location。
- 本机模式可安装订阅服务、查看自用链接、创建和维护本机分享订阅。
- 本机模式可执行本机同步、流量/限额和状态备份。
- 本机状态存在旧远端源、`allowed_sources=["*"]` 且 `remote_enabled=true` 时，同步和发布均不解析、请求或合并远端内容。
- 本机模式看不到远端、Peer 和控制面操作。
- 本机转主控后 groups.json、订阅用户和本机源保持不变。
- 主控初始化独立安装控制服务和 WireGuard 内网 location，不依赖公网订阅服务。
- 主控关闭控制面后执行本机同步：不运行远端阶段，也不重装或启动控制服务。
- 本机存在活动公网发布或受管同步 cron 时转被控：转换失败，角色、服务、cron 和数据均不变。
- 被控残留同步 cron 或直调 `SyncSubscriptionGroups`：写操作前失败，不执行本机同步。
- 被控直调 `InstallSubscription`：证书、Nginx、防火墙和控制服务均不变化。
- 被控收到主控同步后不刷新历史残留的公网订阅配置。
- 被控仍无法进入本机发布、流量治理或备份入口。
- 主控现有发布、多服务器和维护菜单行为不回归。

## 完成标准

- Reality 安装、主控初始化和被控初始化均不会隐式申请公网订阅证书。
- 本机或主控安装订阅服务时，证书准备是明确且独立的前置步骤。
- 缺少证书时不会产生引用不存在文件的 Nginx 配置，也不会降级 HTTP。
- 被复用证书必须有效、覆盖订阅域名并匹配私钥；独立订阅证书可自动续期且续期后 Nginx 使用新证书。
- 本机用户无需初始化 WireGuard 即可完整管理单机订阅。
- 状态损坏不会被当成本机授权，且本机同步和发布都不会接触远端源。
- 菜单、cron 和自动命令使用相同角色边界，被控不能绕过菜单触发本机发布或同步。
- 公网订阅、本机同步和 WireGuard 控制服务之间不存在隐式安装依赖。
- HTTP-01 的 Nginx、80 监听和临时防火墙状态，以及订阅新旧端口规则，均能在失败时恢复。
- 已安装订阅服务可使用不同于 `currentHost` 和 Reality entry 的域名，并可正常检测与更新。
- 未新增持久化角色或状态格式，现有主控/被控行为兼容。
- 定向测试和相关现有回归全部通过。

## 非目标

- 不新增 `standalone` 持久化角色。
- 不改变 Reality 协议或 entry 行为。
- 不把 Reality entry 自动绑定为订阅域名。
- 不增加 HTTP 订阅发布模式或 80 到 HTTPS 的跳转站点。
- 不在本计划实现 Reality 与订阅服务共享公网 443。
- 不支持订阅端口与其他 Nginx 站点共享；只放行当前受管订阅监听的幂等更新。
- 不新增每域名一套续期框架；复用 acme 安装目标和现有 cron。
- 不自动拆除或迁移本机转被控前的公网服务与同步 cron；仍活动时直接阻止转换，订阅数据和证书不删除。
- 不新增依赖、状态格式、菜单层级以外的功能或无关重构。
- 不手工修改 `SCRIPT_VERSION`；版本号由发布自动化维护。
