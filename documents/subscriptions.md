# 🔗 订阅与用户

[🏠 返回首页](../README.md#文档导航) · [🌍 English](en/subscriptions.md)

原生版从 `订阅与用户` 发布 HTTPS 订阅、管理分享范围和流量额度，并通过 WireGuard 接入被控服务器。容器部署见 [Docker 版使用指南](docker-guide.md)。

## 订阅菜单

🔗 原生版的本机与主控首页共用以下入口。安装发布服务后会执行一次完整同步，看到「订阅已发布」再查看链接。

| 菜单 | 用途 |
| --- | --- |
| 📦 `1. 安装/更新发布服务` | 配置公网 HTTPS 入口并同步订阅。 |
| 🔗 `2. 查看当前订阅链接` | 选择已发布的管理员订阅或分享订阅，复制所需格式的链接。 |
| 👥 `3. 分享订阅` | 新建、编辑、启用或停用分享订阅。 |
| 📊 `4. 流量与限额` | 查看已保存的用量、设置流量额度和处理超限订阅。 |
| 🔄 `5. 立即完整同步` | 同步本机和所有已启用来源的账号，更新订阅发布。 |
| 🧰 `6. 订阅同步` | 配置自动同步及间隔，查看状态、排障和备份恢复。 |

| 状态 | 菜单形态 | 适合做什么 |
| --- | --- | --- |
| 🟡 未初始化 | 本机订阅首页提供发布、链接、分享、流量和同步；末尾提供启用主控协同、接入主控 | 单机先安装发布服务即可使用订阅；需要多服务器时再选择主控或被控。 |
| 🟢 主控 | 主控首页与本机订阅首页共用发布和订阅入口，末尾提供被控服务器和本机控制面 | 查看管理员订阅与分享订阅，创建分享订阅、添加被控服务器、执行同步和限额治理。 |
| 🔵 被控 | 被控首页直接提供接入、状态、凭据和控制面动作 | 粘贴主控邀请、提供本机节点给主控、查看 WireGuard 与同步状态。 |

<a name="链接格式"></a>

## 🔗 选订阅和链接格式

打开 `订阅与用户 → 查看当前订阅链接`，先在列表中选管理员或分享订阅，再复制结果里的「默认订阅」链接。如果结果同时显示 Clash Meta 或 sing-box 订阅，可按客户端选择对应链接。

- 👤 **管理员订阅。** 本机模式发布本机协议配置中的节点。主控模式同时汇总已启用被控服务器返回的可用节点。
- 👥 **分享订阅。** 按每条订阅选择的节点范围发布。需要包含本机与全部被控时，将节点范围设为「全部」。

<a name="创建分享"></a>

## 👥 创建分享订阅

1. 在本机或主控首页运行 `安装/更新发布服务`。已有公网发布服务时，可直接进入 `分享订阅`。
2. 首次进入「分享订阅」会直接打开新建向导。已有分享订阅时，选择 `+ 新建分享订阅`。ID 可使用英文字母、数字、下划线和短横线，最多 64 字符，例如 `team-a`。用逗号分隔可批量新建。
3. 选择节点范围和流量上限。节点范围直接回车默认只选本机（`main`），输入 `*` 选全部。流量上限回车或填 `0` 表示不限。
4. 保存后会立即同步，并在核心配置写入托管账号 `sub_<ID>`。同步完成后，可从分享订阅详情或首页的 `查看当前订阅链接` 复制链接。

`分享订阅` 与 `流量与限额 → 管理分享订阅与额度` 共用列表和详情。两处都能查看已保存的用量、修改额度、启停或同步，并支持多选。输入错误可在当前字段修正，草稿保存后才会写入。

<a name="接入被控"></a>

## 🌐 接入被控服务器

1. 在主控选择 `启用主控协同`，再从 `管理被控服务器 → 创建被控邀请` 输入被控别名。主控会预留 WireGuard 地址。
2. 在被控选择 `接入主控` 并粘贴邀请。脚本使用邀请中的地址并导入主控 Peer。完成后复制接入回执。
3. 回到主控，在 `管理被控服务器 → 完成被控接入` 粘贴回执。脚本按预留别名写入 Peer、服务器源和控制 Token，随后执行完整同步。

首次接入前，若这台被控已运行公网发布或受管同步定时任务，先按提示停用发布或关闭自动同步。已发布时可从本机或主控首页的 `9. 停用发布服务` 停止公网链接刷新，已保存的订阅和节点配置会保留。

🔒 邀请、回执和旧版被控凭据都应通过可信通道传递。待完成邀请可按别名查看或取消，丢失时取消后重建。旧版 `main` / `controlled` 凭据用于维护已有连接。控制 API 通过 WireGuard 隧道内的 HTTP 访问，客户端继续通过公网 HTTPS 获取订阅。

<a name="同步恢复"></a>

## 🔄 同步与恢复

- 在 `管理被控服务器 → 管理已接入服务器` 选择一台被控，可连续更新凭据、启停、检查连接、同步或移除。停用会清理远端托管账号，并保留 Peer、Token 和历史状态。启停、更新凭据和移除后都会立即同步。
- 完整同步先处理本机配置，再处理被控快照。部分来源失败时，发布本次成功的来源并标记「部分失败」。仅使用远端来源的订阅若没有可用节点，会沿用上一版非空的默认订阅产物。没有可沿用产物时，本轮发布失败并保留现有公网文件。本机失败或远端结果整体无效时，保留整版公网订阅。
- 被控节点配置变更后，会通过 WireGuard 通知主控。开启自动同步时，主控会重新生成本机节点、拉取已启用来源并更新原 HTTPS 链接。通知失败时，请在主控运行 `立即完整同步`。分享订阅和被控服务器的手动管理动作会执行一次同步，并保留自动同步设置。

**💾 状态备份。** `订阅同步 → 状态备份与恢复` 管理 `/etc/padm/subscribe_groups/groups.json`。恢复备份或重建前，输入 `yes` 确认，脚本会先备份当前状态。

状态文件采用 `version: 6` 单组根对象，分别记录 Xray 和 sing-box 的流量基线，汇总值按需计算。首次读取旧版 2 至 5 时会原子迁移，并按目标版本保存 `groups-pre-v3-migration-*` 至 `groups-pre-v6-migration-*` 备份。v5 的聚合基线会保留到首次完成新版采集。多组、其他旧版结构或字段校验失败的状态会被拒绝。

## 订阅与控制地址

- 🌍 客户端订阅走 `/s/default/...`、`/s/clashMeta/...`、`/s/sing-box...` 等 HTTPS 路径。
- 🔒 主控/被控控制接口走 `/s/control/...`，只通过 WireGuard 内网访问，不提供公网 HTTP/HTTPS 来源回退。

配置路径和宿主服务管理见 [⚙️ 服务与系统运维](operations.md)。
