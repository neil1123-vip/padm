Preparing a handoff

Delivery without confusion

A delivered photograph should be easy to identify, easy to open and easy to relate back to the collection that produced it.

Before exporting, write the destination beside the collection name. “Web gallery”, “small print” and “full-resolution handoff” may need different dimensions or formats. A clear destination prevents one export from being reused by accident.

Read the brief literally

Record the required dimensions, file type, colour space, naming rule and delivery method. If a requirement is missing, write the assumption you are making rather than silently choosing one.

  • Which files are included?
  • What is the longest edge or print size?
  • Should metadata stay embedded?
  • Where should the recipient find the files?

These questions are short enough to answer in a collection note and specific enough to check after export.

Make the export traceable

Keep the subject identifier the same as the source, then add the intended use. A small version number is useful when a delivery is revised.

2025-09-04_woodland_004_web-v1.jpg
2025-09-04_woodland_004_print-v2.tif

Open the exported file itself. Check its dimensions, crop, colour and any metadata that should not leave the archive. A preview inside the editing application does not confirm what was written to disk.

Record what was sent

Add a dated delivery line to collection.txt or a nearby note:

Delivered: 2026-10-12
Files: 2025-09-04_woodland_004_web-v1.jpg
       2025-09-04_woodland_008_web-v1.jpg
Destination: small web gallery
Checked: dimensions and crop opened after export

Keep the exact file names. If a replacement is sent later, record that as another line instead of rewriting the earlier delivery.

A handoff is complete when another person can tell what each file is for without opening the editing project.
