Choosing what to keep

A useful archive keeps the material that would be difficult to recreate and the context needed to understand it later.

Do not begin with a target number of files. Begin with the questions a future version of you may ask: what was the original, what was changed, and which version was actually used?

Keep the source material

Camera originals, scans or contributed source files usually belong in the archive even when they are not attractive. They preserve choices that a finished export has already hidden. Keep them in an originals/ folder and avoid editing them in place.

If a source is unavailable, record that fact beside the collection. A note that says “original supplied as JPEG only” prevents a later reader from assuming that a raw file is missing by accident.

Keep versions with a reason

Not every experiment deserves a permanent copy. Keep a version when it records a meaningful crop, a different output size, a delivered file or a decision that would take time to reproduce.

FileKeep when
OriginalIt is the source or the only copy of the source.
Working versionIt explains a live choice or can still be reused.
ExportIt was shared, printed or prepared for a named destination.
ExperimentIt records a result worth comparing; otherwise remove it after review.

When two files look identical, compare their names, dimensions and context before deleting one. A duplicate-looking export may be the only version with the correct colour profile or delivery size.

Write down the decision

Add one line to collection.txt when you remove or retain an unusual file. For example:

Kept 001_print.tif because it was used for the signed proof.
Removed three temporary crops after the web export was approved.

This record makes future cleanup easier. It also keeps a later reviewer from repeating the same comparison simply because the reason disappeared.
