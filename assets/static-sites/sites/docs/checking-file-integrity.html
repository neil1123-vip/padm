Checking file integrity

A completed copy is only useful if the files can be read and their relationship to the source is still clear.

Integrity checks do not need to run after every click. Use a small sample after an import, a large move or a change to the backup destination. The aim is to catch a bad path or incomplete copy while the source is still available.

Compare a small sample

Select one original, one edited version and one collection note. Compare their file sizes and, when your tools support it, their checksums across the source and destination.

Sample
- originals/woodland_004.raw
- exports/woodland_004_web-v1.jpg
- collection.txt

A checksum match shows that two files contain the same bytes. It does not show that the photograph is the right version for a particular use, so pair the comparison with the context in the collection note.

Open the actual files

Read the restored note and open the restored photographs with an ordinary viewer. Check one large source, one compressed export and one file from a different folder. A copy that passes a checksum check but cannot be opened still needs attention.

  • Confirm the image has the expected dimensions.
  • Check that the export is not zero bytes or truncated.
  • Read the note in a plain text editor.

Record the result

Write down the date, destination, sampled files and outcome. Keep the record near the archive rather than only in a terminal history.

Integrity check: 2026-10-12
Destination: separate archive copy
Sample: woodland_004.raw, woodland_004_web-v1.jpg, collection.txt
Result: opened and matched
Next: check a different collection after the next import

A small recorded check is more useful than a large check nobody can date or repeat.

When a comparison fails, keep both copies until the cause is understood. Recopying immediately can erase the evidence needed to find the faulty path or device.
