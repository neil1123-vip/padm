Writing a collection note

A short collection note should help a future reader understand the folder without requiring the application that created it.

Keep the note in the collection folder and use a plain text format. It should open on a new computer, remain readable after a software change and be easy to update during ordinary work.

Start with purpose

Say what the collection contains and why it exists. A subject, an approximate date and the intended use are usually enough to orient somebody before they inspect individual files.

Use a small, repeatable format

Labels make the note scannable. They also make missing information visible. A simple example:

Collection: Woodland light studies
Date: September 2025
Purpose: Web journal and small print
Originals: camera files in originals/
Working: edits in the catalogue named below
Exports: web-v1 and print-v2
Credit: Unsplash source recorded in the project README
Open question: confirm whether 004 has a larger original

Use the labels that answer real questions in your own archive. Do not create a field simply because another system has one.

Update while the decision is fresh

Add a line when a file is delivered, moved, renamed or deliberately removed. Keep older entries when they explain a past decision. A dated note is more useful than an apparently current sentence that hides the change.

  • Use approximate dates when precision is unknown.
  • Name the actual folder or file, not only a project nickname.
  • Mark unresolved items with a next action.

The note is part of the collection, not an introduction that can be discarded after the first import.

Read the note after moving a sample collection to a temporary folder. If it still explains the files, its format is doing enough work.
