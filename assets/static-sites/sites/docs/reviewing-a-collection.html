Maintaining the archive

Reviewing a collection

Open an older folder as though somebody else had organised it. A short review can expose the details that seemed obvious when the photographs were new.

Start with one completed collection. Keep the review separate from any large cleanup. Finding a confusing name is a reason to record a question, not a reason to rename the whole archive immediately.

Read the context first

Open collection.txt before the editing application. Can you identify the subject, the originals and the selection intended for sharing? Follow one reference in the note and confirm that the named file is present.

  • Replace a vague instruction such as “use the new one” with an exact file name.
  • Distinguish the date of a photograph from the date of an edit or delivery.
  • Record an uncertain date as approximate rather than giving it false precision.
  • Keep any image credit or permission note beside the collection it describes.

Check one photograph across its versions

Choose a photograph with both an original and a finished export. Open each file, compare the framing, and check that their names still make the relationship clear. If editing instructions live in a separate catalogue, note where that catalogue is kept.

QuestionA useful record
Which export was shared?The exact file name and its destination or intended use.
Why are there two crops?A short explanation, such as landscape print and square web version.
Is the backup current?The last copy date and the result of a separate recovery check.
What remains unresolved?A named file and a concrete next action.

Do not infer that two similar thumbnails are duplicate originals. A crop, an exposure adjustment or a different source file may be hard to see at that size. Keep uncertain files while you compare their contents and context.

Leave a brief review note

Add a dated entry to the collection note. Say what was checked, what changed and what still needs attention. This gives the next review a starting point without turning maintenance into a separate database.

Review: 2026-10-12
Checked: source and web export for woodland_004
Changed: recorded the exact delivered export name
Recovery: not checked in this review
Next: restore a sample from the separate copy

Checking the folder structure does not verify a backup. Use the small recovery check separately and record its actual result.

Make the next review smaller

Fix the clear omissions while they are in front of you, then stop. If several collections have the same problem, write one naming rule before making a batch change, and try it on a copied collection first.

A useful stopping point is simple: the files you inspected open, their relationships are understandable, and any remaining uncertainty is written down. The rest can wait for another pass.
